# Change request

## Problem

What is wrong, missing, confusing, or worth improving?

## Goal

What outcome should this change produce?

## Expected behavior

Describe the observable behavior after the change.

## Acceptance criteria

- [ ] The requested core behavior works.
- [ ] Relevant regression/quality checks pass.
- [ ] User-facing behavior is manually verified when automated tests are insufficient.

## Non-goals

List adjacent work that is intentionally excluded.

## Verification

State how completion will be proven: focused tests, full checks, manual flow, UI inspection, and/or production smoke test as applicable.

## Notes

Record constraints, related PRs/issues/specs, or implementation context only when useful.
